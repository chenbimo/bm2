# 02 · 项目身份与状态目录

- 状态: active
- 覆盖测试: 见文末「条目 → 测试」表
- 与代码对账: 2026-10-13

## 一个 bm2.toml 管一个项目

`bm2.toml` 在项目目录里,配置单个应用(一到多个实例)。CLI 读的是**当前目录**那一份。

项目名规则:`[A-Za-z][A-Za-z0-9_]*`;在所有已注册项目中必须唯一。

## 身份 = 名字 + 规范化的配置路径

名字是身份的主体:状态目录、日志、监督策略、通知配置全挂在它上面。因此**同名但不同配置文件必须拒绝启动**,错误信息要点名占用者的路径。

判据用规范化后的真实路径(`realpath`),所以同一个文件经由软链、`..` 或相对路径到达时仍算同一个项目。**同一个项目重新 `start` 必须放行**——那是应用配置变更的正常路径。

拒绝时给出两条出路:改名字,或先 `bm2 remove` 掉占用的那个。

## 状态目录布局

`<state_dir>` 默认 `$HOME/.bm2`,可由 `BM2_HOME` 覆盖;启动时校验目录归属(它持有控制面令牌)。

```
<state_dir>/
  bm2d.events.jsonl bm2.events.jsonl bm2d.log   # 守护进程自身,不属任何项目
  daemon.endpoint                                # 端口 + 令牌,原子替换,0600
  <name>/
    project.json          # 登记记录:config_path + stopped
    <name>-<id>.json      # 每个实例的状态,恢复时用于收养
    logs/                 # 见 06
```

一级目录才可能是项目;嵌套目录不是。

## 项目是一个值

一个项目的全部状态装在 `Project` 里,**以名字为键的表只有 `projects` 一张**:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `config` | `AppConfig` | 解析并校验过的配置 |
| `config_path` | `String` | 规范化后的 `bm2.toml` 路径,同名保护的判据 |
| `instances` | `Array[Instance]` | 实例数组;**唯一会被整体替换**的字段 |
| `stats` | `StatsWindow` | 窗口内峰值内存与重启次数 |
| `storm_hits` | 重启时间戳数组 | 风暴窗口,只追加与裁剪 |
| `probe_done` | `Map[Int32, UInt64]` | 实例号 → 已探测的代号 |
| `restarting` | `Bool` | 重启中标记(拒绝并发重启) |
| `removing` | `Bool` | 退役中标记 |
| `stopped` | `Bool` | 停止标记,持久化在 `project.json` |

关于 `mut`:值语义字段只在**整体替换**时才需要 `mut`。`instances` / `stats` / `storm_hits` 会被整体替换,所以有;`probe_done` 只在原地改 Map,所以没有。

新增项目级状态就是给 `Project` 加字段——不是新开一张表加一处注销。散落的表会让「注销」变成一件必须记得很多次的事,而人一定会忘:本轮就漏过一次(`config_paths` 从未被清除),后果是静默的跨项目串味,重名再注册时拿旧路径去比对。

## 注销只有一个出口

`Supervisor::forget_app` 是释放项目状态的唯一地方。`check_removals` 只调它一次,不自己清表。

## 边界情形

| 情形 | 表现 |
| --- | --- |
| 同名、同配置文件 | 放行,刷新配置(等价于一次完整重启) |
| 同名、不同配置文件 | 拒绝,报占用者路径与两条出路 |
| 不同名字、同一个配置文件 | 拒绝(一个配置文件只能是一个项目) |
| 项目名非法 | 配置校验期拒绝,退出 1 |
| 软链 / `..` / 相对路径到达同一文件 | 规范化后判为同一个项目 |
